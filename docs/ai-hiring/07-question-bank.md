# 07 · Interview Question Bank

Each job has its own bank of interview questions, generated by AI and editable by the recruiter. Scoring needs every question to have an **ideal answer** and **expected keywords**.

## Generator: `libs/interview/question-generator.js`

```js
export async function generateJobQuestions({ job, count = 8, existing = [] }) → Question[]
export async function generatePersonalisedQuestions({ job, candidate, count = 2 }) → Question[]
// Question = { question, category, difficulty, idealAnswer, expectedKeywords[], scoreWeight }
```

**Mix for `count = 8`** (scale proportionally for other counts):
- 1 warm-up (`role`, easy): "Walk me through your background and why this role interests you."
- 4 `technical` (2 medium, 2 hard), directly from required skills and tech stack
- 1 `role` (practical scenario for this job)
- 2 `behavioral` (STAR-style: "Tell me about a time…")

**Prompt rules:**
- Questions must be answerable **verbally in 1–3 minutes**. No coding on a whiteboard, no "write a function".
- Each question is **one sentence**, under 30 words, with no multi-part questions.
- `idealAnswer`: 3–6 sentences describing what a strong answer contains.
- `expectedKeywords`: 3–8 short terms a good answer would mention.
- `scoreWeight`: 1 (warm-up) to 3 (core technical).
- Don't duplicate anything in `existing`.
- Return JSON: `{ "questions": [ ... ] }`.

**Validation in code:**
- Drop questions with an empty `idealAnswer`, < 2 keywords or > 40 words.
- Re-number `orderIndex` with the warm-up first and behavioral questions last.
- Retry if fewer than `count - 2` survive.

**Personalised questions** (`hiring_config.personalisedQuestions` 1–2): built from `fit_analysis.concerns` and `skillMatch.missing`, e.g. "Your resume doesn't mention Docker; how have you handled deployments?". Stored with `candidate_id` set, and appended after the technical block for that candidate only.

## When questions are generated

- The worker job `ensure-questions {jobId}` creates the bank if the job has **no active job-wide questions**. It is idempotent: hold a Redis lock `lock:questions:{jobId}` for 60s.
- The recruiter can click **Generate** (append) or **Regenerate** (deactivate AI questions and create new ones; manual questions are kept).
- At interview start, the engine freezes the active questions into `interviews.question_snapshot`, so later edits don't affect running or finished interviews.

## APIs (all withAuth + job ownership)

| Method & path | Purpose |
|---|---|
| `GET /api/hiring/jobs/[jobId]/interview-questions` | List (job-wide; `?candidateId=` also includes personalised) |
| `POST /api/hiring/jobs/[jobId]/interview-questions` | Add a manual question `{question, category, difficulty, idealAnswer, expectedKeywords, scoreWeight}` |
| `POST /api/hiring/jobs/[jobId]/interview-questions/generate` | Body `{ mode: "append" | "replace", count? }` |
| `PATCH /api/hiring/interview-questions/[questionId]` | Edit fields, `isActive`, `orderIndex` |
| `POST /api/hiring/jobs/[jobId]/interview-questions/reorder` | Body `{ ids: [...] }` |
| `DELETE /api/hiring/interview-questions/[questionId]` | Soft delete (`isActive=false`) if used in any interview snapshot; hard delete otherwise |

## UI: `app/dashboard/recruiter/jobs/[jobId]/interview-questions/page.js`
- A list of cards: question, category badge, difficulty badge, weight, and a collapsible ideal answer + keyword chips.
- Drag to reorder (`@dnd-kit/sortable` is already a dependency), an active toggle, and edit/delete.
- Header: "Generate with AI" (with count input), "Add question", and a warning banner if any active question lacks an ideal answer.
- Linked from the job card and the job candidates page ("Interview questions" button).

## Acceptance
- Generating for the fixture JD yields 8 valid questions, each with an ideal answer and ≥ 3 keywords.
- Editing a question after an interview started doesn't change that interview's snapshot.
