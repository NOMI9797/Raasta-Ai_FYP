## 8. Background jobs, Redis keys and channels

### 8.1 Hiring queue job types (`workers/hiring-worker.js` → `handlers`)

| Job type | Payload | Timeout | What it does | Enqueued by |
|---|---|---|---|---|
| `ping` | `{fail?}` | 10 s | Health / test | tests, admin |
| `screen-candidate` | `{candidateId}` | 60 s | Fit-score one candidate; debounce a shortlist run | apply route, screen routes, agent |
| `shortlist-job` | `{jobId}` | 60 s | `applyShortlist` (skipped if an agent manages the job) | `screen-candidate` (30 s debounce) |
| `ensure-questions` | `{jobId}` | 90 s | Build the question bank if none | `queueAfterShortlist`, `sendInvite` |
| `personalise-questions` | `{candidateId}` | 60 s | 1–2 gap-based questions | `queueAfterShortlist`, agent |
| `send-invite` | `{candidateId, resend?, waits?}` | 30 s | Create interview row + email link (waits ≤ 10×30 s for questions) | shortlist hook, invite route, agent |
| `send-reminder` | `{interviewId}` | 30 s | Rotate token + reminder email | 15-min sweep |
| `assemble-recording` | `{interviewId, kind?}` | 5 min | ffmpeg join of uploaded parts | upload route (final part) |
| `analyse-interview` | `{interviewId, force?}` | 15 min | Voice/behaviour/emotion analysis; re-queues every 30 s while uploads finish | interview end, re-analyse, sweep |
| `finalize-candidate` | `{candidateId, interviewId}` | 90 s | Final score + LLM summary + suggested decision | `analyse-interview` |
| `agent-advance` | `{runId}` | 5 min | One supervised-agent tick | triggers, 15-min sweep |
| `send-outcome-email` | `{candidateId}` | 30 s | Outcome email if enabled | `applyDecision` |

Periodic sweeps (every 15 min and once at start): **expire invites**, **queue reminders**, **advance recruiter agents**, **close stale interview sessions**. Retries: 3 attempts, delay `2^attempt × 10 s` (or Groq `retry-after`), then dead-letter.
